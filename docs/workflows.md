# Workflows and release scope

Crosscript is a native Apple Silicon macOS translation and transcription workbench. Its four workflows are included in the published [0.1.0 build 7 preview](https://github.com/yqia03/crosscript/releases/tag/v0.1.0-preview.7). The App is `Crosscript.app`, with display and executable name Crosscript; SwiftPM targets and compatibility identifiers retain their existing names. Earlier releases, including build 6's `TranslationWorkbench.app`, remain unchanged. See the [upgrade instructions](getting-started.md#upgrade-from-translationworkbenchapp) before replacing an older App.

| Workflow | Scope | External processing |
| --- | --- | --- |
| Text and Markdown | Explicit submission, source/translation comparison, editable results, history and text/bilingual Markdown export | Selected OpenAI-compatible text provider |
| PDF translation | Managed BabelDOC runtime, selectable output/layout settings, source-preserving import and export | Selected PDF/text provider when translation is requested; explicit local modes are not translated output |
| Recording and post-recording transcription | Microphone or system audio, import, preserved audio, editable transcript and export | Supported recorded-audio provider when transcription is requested |
| Live bilingual captions | Locally saved recording, source/translation text and optional caption window | Adapted Gemini Live protocol with separate credentials |

For the next build from this source, new PDF submission forms default to both translated and bilingual PDFs. Either output can still be selected on its own; bilingual layout and watermark choices remain available. Current form choices survive navigation and starting a new PDF project. Saved task options, history retries and older records without output settings retain their original meaning; existing files are not regenerated. Outputs are previewed and exported individually. “New project” opens an empty PDF import list and clears its displayed selection while retaining history, results, pending saves, service/settings and running or queued tasks. Late imports stay in history and completed tasks do not refill the new list; explicitly import or reopen history to add material. The PDF page’s New project button and Command-N share this action, without starting translation or preparing components again.

Local material storage does not imply offline cloud processing. API credentials belong in macOS Keychain. Entering history, editing text and creating an empty recording or PDF workspace must not itself submit a new provider request. Service and model compatibility are scoped by workflow; text API compatibility is not proof of audio/live support.
